# 进度日志 05 · WMI 逃逸替代 explorer（2026-08-10 下午 1:20）

- **时间**：2026-08-10 13:20
- **会话**：ailauncher-v3-rewrite（后台 job abc440da）续
- **性质**：用户真机验收进度日志 04 的修复 → 反馈「依旧会被杀」→ 定位 explorer 逃逸不生效 → 换成确定性的 **WMI `Win32_Process.Create`** 逃逸。

## 现象

从 WezTerm 启动 ailauncher → 弹 Alacritty 窗口 → 关 WezTerm 标签 → **窗口依旧被杀**（进度日志 04 的 explorer 逃逸没逃出去）。

## 为什么 explorer 逃逸不生效

BREAKAWAY 直拉在 WezTerm 被拒（Job 不允许 breakaway）→ 走了 explorer 逃逸。但新起的 `explorer.exe script.vbs` 是 ailauncher 的**直接子进程、仍在 Job 里**；它能逃出去的前提是 ShellExecute 被**委托**给主 explorer（桌面 shell，在 Job 外）。实际行为不保证——它可能就地执行 ShellExecute，于是 wscript→alacritty 的整条链都落在 Job 里，关标签一起被杀。**委托行为是赌注，不可靠。**

## 做了什么（WMI 确定性替代）

`pkg/ailauncher`：

1. **`launch_windows.go`** 新增 `writeWmiVBS(cmdline, cwd)`：生成临时 `.vbs` 调 `GetObject("winmgmts:...").Get("Win32_Process").Create(cmdline, cwd, null, pid)`，用 Create 的 ReturnValue 做 `WScript.Quit rc`。**进程由系统服务 WmiPrvSE 创建——确定在启动终端的 Job/进程树之外**，不赌任何委托行为。
2. **`launchWindowsFallback(argv, wd)`** 改为两层递进：① **WMI**（`wscript.exe script.vbs` 同步等待，退出码 0 判成功）→ ② **explorer**（保留，作 WMI 不可用时的第二选择）。签名增加 `wd`（作为 WMI 创建时的当前目录，gui 路径的 Dir 等价物；tui 路径 argv 里已有 `--working-directory`，双保险）。
3. **`launch.go`**：gui/tui 两个调用点传 `wd`，注释改「WMI/explorer 逃逸」。
4. **`launch_other.go`**：占位签名同步加 `wd`，保证跨平台编译。
5. **测试**：`launch_windows_test.go` 新增 `TestWriteWmiVBS`；**临时冒烟测试 `launch_windows_smoke_test.go`（保留）**：真实跑 `writeWmiVBS` + wscript + WMI 链路，写 marker 验证进程真被创建。

## 踩坑（重要）

- **VBScript 语法**：`rc = obj.Method arg1, arg2`（赋值 + 不带括号传参）是**非法**的，必须 `rc = obj.Method(arg1, arg2)`。初版生成的 vbs 少了对括号，wscript 直接编译失败退出 1。**纯字符串单测（`TestWriteWmiVBS`）抓不到这类问题**——它只校验内容、不校验语法合法性，是真实运行冒烟测试才暴露的。教训：vbs 这类「代码即字符串」的产物必须配套真实执行验证。
- **异步时序**：`Win32_Process.Create` 返回时目标进程刚被创建、未必写完输出；冒烟测试加了最多 5s 的轮询等待。
