# step11 · v4 骨架重构完成：core / cli / ui 三层独立项目（从零重建）

> 2026-08-12。承接 v3（step10 部署）后的整轮重构。旧 v3 Go 源码已整体移入
> `../AI_LAUNCHER_v3_archive/`，本目录从零按 v4 架构重建。

## 做了什么

按「删掉所有旧的无用代码，从零按架构构建，分好项目层级」的指示，把单体 v3 拆成三个独立 Go 项目 + 工作区：

```
AILauncher/
├─ go.work            # use ./core ./cli ./ui
├─ core/              # 逻辑处理层：每条逻辑 = 自注册单元（stage + declared），命令/查询皆有
├─ cli/               # 纯路由微前端：core 按 stage 过滤 → proto-lab → 详细报错；不持有逻辑
└─ ui/                # 前端：TUI（纯 stdlib 全屏重绘），所有逻辑经 cli 端口
    ├─ cmd/ailauncher/main.go   # 唯一入口：无参数→TUI；-i→直达；否则→cli 路由
    └─ tui/            # 页面 + cli_port 接口 + 测试
```

- **依赖单向** `ui → cli → core`，**完全成立**：`cli/port.go` 定义**供应侧端口**
  `type Port interface { Dispatch(argv []string, in io.Reader) (*Result, error) }` 并用**类型别名**
  导出 core 数据模型 `Config/Agent/AgentState/Result`（别名即同一类型，零拷贝），外加 `cli.Text/JSON`
  构造 Result。`*cli.Router` 满足 `Port`；ui **只 import cli**，经 cli 别名命名 core 数据模型，
  不 import core。~~初版走「ui 定义消费侧接口、不 import cli、仅对 core 做值类型引用」~~（见「为什么」修正）。
- **stage 运行时分级（A 阶段）**：默认只暴露 `stable`；`experimental` 打包但需
  `AILAUNCHER_EXPERIMENTAL=1` 才可见；draft/checking/abandoned 不参与路由。cli 的
  `visibleUnits()` 统一过滤，cap / 详细报错共用这一信息源。
- **命令面全新**：`run/list/version/help/migrate/resolve/cap/config/state get|put`，
  退出码 0/1/2（未知命令·用法 = 2，且返回**详细信息**：名字 + 能力清单 + cap/help 提示）。
- **TUI 全部逻辑经 cli 端口**：session 只持 `cli.Port` + `*cli.Config`（引导数据）；agent 状态
  逐个 `state get/put`，启动走 `run`。页测注入 stub CLI（stub 也经 `cli.Text/JSON` 构造，不碰 core），无需 TTY。

## 为什么

- v3 的单体里「TUI 直接 import 领域库」导致逻辑只有一处没错，但命令面/实验面没有独立演进位；
  cli 作为纯路由端口后，脚本面与 TUI 共享同一路由，未来 GUI 也只要实现同一端口。
- 计划里 `Dispatch(argv)` 加上了 `in io.Reader`：TUI 在 raw 模式下不能读 os.Stdin 喂 JSON，
  `state put` 的 JSON 改走 `ctx.In`（TUI 传 `strings.NewReader`）。
- **ui 与 core 彻底隔离（修正）**：初版走「ui 定义消费侧接口 + 引用 core 值类型」，被用户质疑
  「真的不能彻底隔离 UI 和 core 吗」。修正为 **`cli/port.go` 供应侧接口 + 类型别名**：端口接口归
  cli（供应方），core 数据模型经别名导出，ui 只 import cli 一个包，`ui → cli → core` 单向依赖
  完全成立，ui 对 core 零引用。别名是 Go 的 identity（零拷贝），数据模型仍共享同一份 struct。
  `cli.Text/JSON` 让 ui 测试桩也不需要 import core。验证：`grep '"core"' ui/` 零命中 + 全量测试绿。
- **state put 归一化补丁**：冒烟时发现部分 JSON（缺 removedDirs 等）落盘成 `null` 数组。
  把 migrate 的 null→[] 归一化提取成 `AgentState.normalize()`（单点），state put 与 migrate 共用。

## 后果

- 三模块各自 `go build/test/vet` 全绿（core 50 + cli 14 + ui 27 用例），四平台（win/linux/darwin/freebsd）
  交叉编译通过。根目录 `go build ./...` 因根非 module 不可用，用 `./core/... ./cli/... ./ui/...`。
- 旧 `pkg/ailauncher` / `internal/tui` / `cmd/ailauncher` 与 Node 单文件 `ailauncher.js`/`.cmd`
  已从项目根移除（前者在 archive，后者也归档了一份）。
- 数据文件（config.json/data.json/config.sample.json）留在根，格式已是 v4 agents[]，无 legacy tools[]。
- 行为差异：`run <agent> [path] [KEY=V|arg]` 的 path 是**首个非 KEY=V 的 token**；TUI 内部对
  空 workdir 用空串占位 path 槽位，避免 args 首个 token 被误当路径（`buildRunArgv` 有测试钉死）。
- 部署副本 `D:\Coding\Scripts\ai-launcher\` 已更新为 v4 二进制 + 数据验证（migrate 报已 v4 形态）。
