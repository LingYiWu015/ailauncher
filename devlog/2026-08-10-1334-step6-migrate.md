## 背景

- `config.json` 一直是旧 Node 版 `tools[]` 格式，v3 靠 `LoadConfig` legacy 兼容只读映射成 `agents`，**文件本身从未升级**。
- `data.json` 有旧残留：`claude.removedCmds: null`（应为 `[]`）。
- PROJECT_OVERVIEW「B. 短期可做」第 1 条：加 `--migrate` 命令把 `tools[]` 落成 `agents[]`，顺手清理 data.json 残留。

## 做了什么

1. **新增 `pkg/ailauncher/migrate.go`**：
   - `MigrateConfig(path) (bool, error)`：检测文件是 `tools` 旧格式（有 tools 且无 agents）→ 经 `LoadConfig` 映射后写回 v3 `agents[]`，**保留** terminal / defaultDirectories / agent 全字段；已是 v3 则不动文件（no-op）。
   - `configNeedsMigration(path)`：读 raw JSON 判断「有 tools 无 agents」。
   - `MigrateState(path) (bool, error)`：遍历 `State`，把 nil 的 Directories/RemovedDirs/Commands/RemovedCmds 归一化为 `[]`；无变化不动文件。
   - 两条都返回「是否发生变更」，幂等（二次运行 no-op）。
2. **`cli.go`**：新增 `--migrate` / `migrate` 分支 + `migrateCLI`（打印每项变更；都无变更则提示已是 v3）+ usage 补一行。
3. **新增 `migrate_test.go`**（5 例）：
   - `tools[]→agents[]` 迁移 + 字段保真（terminal/defaultDirectories/display/desc/rootDir）+ 二次迁移 no-op + 迁移后可 LoadConfig 直接读回。
   - 已是 v3 → 文件**字节级不动**。
   - 文件缺失 → 无错误 no-op。
   - data null 归一化 + 字段保真 + 二次 no-op。
   - data 本就干净 → 不动。
4. **应用到真实数据文件**（用户出门，先备份再迁移）：
   - `cp config.json config.json.bak-v3`、`cp data.json data.json.bak-v3`。
   - `.\ailauncher.exe --migrate` → 「config.json: tools[] → agents[] 已迁移」「data.json: null 数组已归一化为 []」，exit 0。
   - 复验：`--migrate` 再跑 → 「已是 v3 格式」；`--list` → 5 个 agent 齐全；`data.json` 的 removedCmds 已是 list。

## 后果 / 验证

- 迁移后 `config.json` 为干净 v3：`agents[]` 含全部 5 个 agent，`env:{}`/`args:""`/`directories:[]` 等空值因 `omitempty` 不再落盘（语义等价，更干净）。
- legacy 兼容读取保留：即使拿旧 `tools[]` 文件回来仍能读（`LoadConfig` 逻辑未动）。
- `--migrate` 幂等、可逆（备份在 `config.json.bak-v3` / `data.json.bak-v3`）。
- 全平台构建/单测/vet/fmt 通过（本轮末尾统一验证）。
